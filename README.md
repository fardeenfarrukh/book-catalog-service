# Book Catalog Service

A REST API for managing a book catalog, including book details, search, and inventory updates. This project is being developed as part of the Amazon Books service assignment.

## Overview

The Book Catalog Service provides endpoints to create, retrieve, search, and update book records. It uses Node.js and Express, with a layered backend structure that separates HTTP routing, request handling, business rules, and data storage.

The current backend uses in-memory storage. It is intended for development and demonstration; book records do not persist when the server restarts.

## Features

- Create a book record.
- Retrieve a book by ID.
- Search books by title or author.
- Filter book searches by genre.
- Update book details while preserving the book's ID.
- Update inventory quantities.
- Validate book data, prices, publication years, and inventory quantities.
- Return appropriate HTTP status codes for validation failures and missing records.
- Run automated API tests using Jest and Supertest.

## Technology Stack

- **Runtime:** Node.js
- **Backend framework:** Express
- **Cross-origin requests:** CORS
- **Automated testing:** Jest and Supertest
- **Frontend:** Vite-based application in the `frontend` directory

## Getting Started

### Prerequisites

- Node.js with npm installed.
- Git, if cloning the repository.

### 1. Open the project

If you have already cloned or downloaded the repository, open a terminal in the project directory.

### 2. Install backend dependencies

```bash
cd backend
npm install
```

### 3. Start the backend

For development:

```bash
npm run dev
```

Alternatively, start the server normally:

```bash
npm start
```

The backend runs on port `5000` by default.

Visit `http://localhost:5000/` to check the service status and view the available endpoint patterns.

### 4. Run the automated tests

Open a terminal in the `backend` directory and run:

```bash
npm test
```

The tests use Jest and Supertest to exercise the Express application. They do not require a separately running backend server.

## API Reference

The following endpoints are implemented by the backend.

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/` | Returns basic service information and endpoint patterns. |
| `GET` | `/books` | Retrieves books, with optional search filters. |
| `GET` | `/books/:id` | Retrieves a book by ID. |
| `POST` | `/books` | Creates a book. |
| `PUT` | `/books/:id` | Updates book details. |
| `PATCH` | `/books/:id/inventory` | Updates a book's inventory quantity. |

### Book Data Model

A book record contains the following fields:

| Field | Description |
|---|---|
| `id` | Unique identifier generated by the service. |
| `title` | Book title. |
| `authors` | Array of author names. |
| `isbn` | ISBN identifier. |
| `genre` | Book category or genre. |
| `price` | Price as a non-negative number. |
| `publicationYear` | Publication year as an integer. |
| `inventoryQuantity` | Available inventory as a non-negative integer. |

### Create a Book

**Request**

`POST /books`

Example JSON body:

```json
{
  "title": "The Hobbit",
  "authors": ["J. R. R. Tolkien"],
  "isbn": "9780547928227",
  "genre": "Fantasy",
  "price": 14.99,
  "publicationYear": 1937,
  "inventoryQuantity": 12
}
```

A successful request returns `201 Created` and the created book record, including its generated ID.

### Retrieve a Book

**Request**

`GET /books/{id}`

Replace `{id}` with the ID returned when the book was created.

A successful request returns `200 OK`. If the ID does not exist, the API returns `404 Not Found`.

### Search Books

**Request**

`GET /books?title=Hobbit`

The list endpoint supports optional `title`, `author`, and `genre` query parameters. Multiple supplied filters can be used together.

Examples:

```text
GET /books?title=Hobbit
GET /books?author=Tolkien
GET /books?genre=Fantasy
GET /books?author=Tolkien&genre=Fantasy
```

### Update Book Details

**Request**

`PUT /books/{id}`

Send the updated book details in the JSON request body. The service preserves the existing book ID rather than replacing it with an ID supplied by the client.

### Update Inventory

**Request**

`PATCH /books/{id}/inventory`

Example JSON body:

```json
{
  "inventoryQuantity": 8
}
```

Inventory must be a non-negative integer. Negative and fractional quantities are rejected.

The current endpoint sets the quantity to the supplied value; it does not perform an increment or decrement operation.

## Validation and Error Handling

The service validates book records before accepting them. Current rules include:

- Title, authors, ISBN, and genre must be provided with valid values.
- Price must be a finite number greater than or equal to zero.
- Publication year must be an integer between 1 and the current year.
- Inventory quantity must be a non-negative integer.

The API uses the following status codes:

| Status | Meaning |
|---|---|
| `200 OK` | The requested operation succeeded. |
| `201 Created` | A book was created successfully. |
| `400 Bad Request` | The submitted data failed validation. |
| `404 Not Found` | The requested book does not exist. |
| `500 Internal Server Error` | An unexpected server error occurred. |

Error responses use JSON and include an error message where applicable.

## Automated Testing

The backend test suite uses Jest and Supertest.

Current tests cover:

- Book creation and retrieval.
- Title search.
- Book-detail updates and ID preservation.
- Inventory updates.
- Rejection of negative inventory and fractional inventory quantities.
- Rejection of missing titles and negative prices.
- Handling requests for nonexistent books.

The test setup clears the in-memory book store before each test to reduce interference between test cases.

Run all backend tests from the `backend` directory:

```bash
npm test
```

## Current Limitations and Future Improvements

The current implementation prioritizes core API functionality and a straightforward local development setup.

Known limitations and potential improvements include:

- **Persistent storage:** The in-memory store loses all records when the backend process restarts. A persistent database has not yet been integrated.
- **Pagination and sorting:** The list endpoint does not currently provide pagination or sorting.
- **ISBN uniqueness:** Duplicate ISBN values are not currently prevented.
- **Concurrency:** Inventory updates do not yet provide database transactions or concurrency control.
- **Operational readiness:** Database configuration, migrations, backups, structured logging, and Docker deployment have not yet been implemented.

These items should be evaluated against the assignment's requirements before being treated as completed features.
